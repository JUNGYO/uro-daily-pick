# 운영 복구 기록 — 2026-09-13

이 문서는 `service-readiness.md`의 로그인 대기 시점 이후에 확인한 운영 상태입니다.

- Supabase 프로젝트가 TCP 연결 시간 초과로 Unhealthy였으며 재시작 후 SQL과 REST 읽기가 복구됐습니다.
- 변경 전 공개 테이블 8개와 공개 함수 정의를 `app_private.release_backups`에 보존했습니다. 백업 ID는 `20260913_service_v1`입니다. 브라우저 역할은 접근할 수 없습니다. 같은 DB 내부 백업이므로 독립적인 재해 복구 백업은 아닙니다.
- 기존 논문 935편, 프로필 9개, 추천 370개를 보존한 상태에서 006–009를 적용했습니다. 트랜잭션 안에서 SQL SHA-256을 검증했으며 `app_private.release_migrations`에 기록했습니다. Supabase CLI의 migration 이력 테이블은 기존 운영 DB에 없었습니다.
- MeSH 데이터는 최대 21회 JSON 문자열로 중복 인코딩돼 215,707,371바이트까지 커져 있었습니다. 반복 디코딩으로 원래 배열을 보존해 82,595바이트로 복구했습니다. 비정상 타입은 0개입니다. 같은 21단계 데이터를 사용하는 회귀 테스트를 추가했습니다.
- 운영 수집 작업에서 최신 논문 38편을 추가했습니다. 분류 단계도 성공했습니다.
- 인증 Site URL의 잘못된 `/**`를 제거하고 앱 루트, 비밀번호 재설정, 설정 화면을 redirect 허용 목록에 등록했습니다.
- Supabase는 기본 이메일 공급자를 사용하고 Resend에는 발신 도메인이 없습니다. 운영자는 현재 보유 도메인이 없다고 확인했습니다. 이메일 개통 전에는 배포된 프런트엔드의 신규 가입·이메일 복구가 준비 중으로 표시되고, 정기 메일 단계는 비활성 상태입니다.

## 원문 운영

`FULLTEXT_IMPORT_ENABLED=true`이면 일일 배치가 최근 30일 수집 논문에서 Europe PMC 공개 원문을 최대 20편 확인합니다. 준비된 문서는 건너뛰고 원문 부재는 7일 후 다시 확인합니다. 일시적 통신 오류는 성공으로 기록하지 않습니다. 실패 기록은 이미 저장된 정상 문서를 덮어쓰지 않습니다.

`FULLTEXT_BATCH_SIZE`는 1–100 범위이며 기본 20입니다. 원문은 비공개 `paper_fulltexts`에 저장됩니다. 기관 구독 원문은 기존 Z8 `fulltext.py --input` 또는 승인된 Elsevier API 경로로 가져옵니다.

원문 외부 모델 전송은 `SUMMARIZE_FULLTEXT=true`로 별도 활성화합니다. 현재 이 설정은 활성화하지 않았습니다. 원문 다운로드·파싱 성공과 원문 기반 AI 요약 성공은 별개의 상태입니다. 운영 요약 모델 요청은 HTTP 400, `API_KEY_INVALID`로 거절됐으며, 최초 검증 예산 `SUMMARY_BATCH_SIZE=1`을 유지합니다.

첫 운영 OA 배치 20편은 원문 부재 20건, 통신 오류 0건으로 완료됐습니다. 기존 카탈로그의 PMID `42315681`은 로컬에서 실제 다운로드·파싱해 34,778자, 13개 절을 확인했습니다. 이 문서의 운영 저장을 요청한 GitHub UI는 500 오류를 반환했고 워크플로 실행이 생성되지 않았습니다. 따라서 이 문서의 운영 저장과 원문 기반 AI 요약은 완료로 간주하지 않습니다. 브라우저 역할의 원문 및 메일 payload 테이블 읽기 권한이 없음을 운영 DB에서 확인했습니다.

## 개통 전 필요한 설정

1. 발신 도메인을 준비해 DNS 검증, Resend 발신 주소와 Supabase SMTP를 설정합니다. 실제 테스트 계정으로 인증과 수신을 확인한 뒤 `EMAIL_AUTH_READY=true`, `EMAIL_DELIVERY_ENABLED=true`, `FROM_EMAIL`을 설정하고 다시 배포합니다.
2. 운영 인증 정책 변경은 자동 승인 검토에서 보류됐습니다. 운영자의 명시적 승인 후 신규 가입 보류와 이메일 확인 필수를 적용합니다. 현재 정책을 적용 완료로 간주하면 안 됩니다.
3. 외부 모델로 원문을 전송하는 설정도 승인 대기 상태입니다. 승인 범위에 맞게 구성한 후 실제 저장된 원문 한 편으로 검증합니다.
4. Gemini API 키를 교체하고 한국어 요약을 실제 저장한 뒤 일일 예산을 높입니다. 로그인된 AI Studio의 기존 유료 프로젝트에 서비스 전용 키를 생성하는 작업도 자동 승인 검토에서 보류됐습니다. 새 키는 생성되지 않았고 기존 키도 변경하지 않았습니다. `recommend-only`는 AI 요약과 별개로 최신 분류 데이터를 사용해 추천만 재생성할 수 있습니다.
5. 독립적인 암호화 백업, 복구 훈련, 공급자 장애 감시가 추가로 필요합니다.

로컬 검증: Python 24개, 프런트엔드 13개, 마이그레이션 9개, Chrome·axe 브라우저 5개. 1440/390/320px 화면을 확인했습니다. 운영자 로그인·새 가입·실제 메일 수신 성공까지 의미하지는 않습니다.

PR #2의 CI는 통과했고 리뷰 가능한 상태입니다. 운영 배포를 촉발하는 병합은 자동 승인 검토에서 거절돼 아직 실행하지 않았습니다. 실제 배포 완료 기록은 별도로 확인해야 합니다.
